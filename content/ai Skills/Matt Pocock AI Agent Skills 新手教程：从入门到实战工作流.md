# Matt Pocock AI Agent Skills 新手教程：从入门到实战工作流

本笔记详细解析了由 Matt Pocock 开发的 AI Agent Skills 工具集。这套工具旨在将数位工程师积累的工程实践（如领域驱动设计、测试驱动开发等）转化为 AI Agent（如 Claude Code、Codex）的可执行技能，从而告别模糊的“氛围编程”（Vibe Coding），实现专业级的软件工程交付。

## 一、 环境准备与安装

在使用这些技能之前，需要将它们集成到 AI 代理的工作环境中。

### 1. 安装步骤

根据使用习惯，有两种主要的安装方式：

- **管理型安装（Claude Code 插件）：** 作为受管束的只读包安装，随作者更新而自动同步。在 Claude Code 会话中运行： `npx skills add mattpocock/skills`
- **开发者型安装（本地文件）：** 将可编辑的技能文件拷贝到项目中，允许自行修改。运行： `npx skills.sh` （支持多种代理，如 Cursor, Codex 等）

### 2. 初始配置

安装完成后，必须在每个仓库中运行一次初始化命令： ==`/setup-matt-pocock-skills`==

该命令会引导完成以下设置：

- **问题追踪器：** 选择使用 GitHub、Linear 或本地 Markdown 文件记录任务。
- **分类标签：** 设置用于分类和分流（Triage）任务的标签。
- **文档布局：** 确定领域文档（如 `CONTEXT.md`）的保存位置。

## 二、 核心工程工作流：技能使用顺序

Matt Pocock 推荐的“主流程”（Main Flow）遵循严谨的软件开发生命周期（SDLC），建议按以下顺序使用相关技能：

### 阶段一：对齐与理解 (Alignment)

在编写任何代码之前，首先要解决“需求模糊”的问题。

1. `/grill-with-docs`**(核心起始技能)**
    - **作用：** 启动一个“盘问”（Grilling）环节。AI 会不断提问，挖掘需求中的模糊点，直到双方达成共识。
    - **产出：** 该技能是“有状态的”，它会实时更新仓库中的 `CONTEXT.md`（统一语言/术语表）和 `ADRs`（架构决策记录）。
2. `/prototype` **(可选：高保真验证)**
    - **作用：** 当讨论无法解决“看起来如何”或“逻辑是否通顺”时，调用此技能生成丢弃型原型代码。
    - **场景：** 复杂的 UI 交互变化或难以通过纸面推演的状态机逻辑。

### 阶段二：规划与分解 (Planning)

当需求清晰后，将其转化为可执行的规格说明。

1. `/to-spec`
    - **作用：** 将之前的对话内容压缩成一份正式的技术规格说明（Specification），并发布到问题追踪器中。
2. `/to-tickets`
    - **作用：** 将规格说明拆解为多个独立的“票据”（Tickets）。每个票据的大小应控制在 AI 代理的一个“聪明区”（约 140k token）内，以便分多次会话完成。
    - **进阶替代：**`**/wayfinder**`。如果项目极其庞大，使用此技能绘制一份“任务地图”，逐个攻克不确定性区域。

### 阶段三：执行与交付 (Implementation)

1. `/implement`
    - **作用：** 逐个执行票据任务。
    - **内部逻辑：** 它会自动调用 `/tdd`（测试驱动开发）技能。
2. `/tdd` **(模型调用)**
    - **作用：** 强制执行“红-绿”循环。先写失败的测试，再编写实现代码，确保逻辑正确。

### 阶段四：评审与提交 (Review)

1. `/code-review`
    - **作用：** 从两个维度审查代码：
        - **标准：** 是否符合仓库的编码规范（参考 Martin Fowler 的代码异味）。
        - **规格：** 是否忠实实现了原始的规格说明。
    - **结束：** 评审通过后，自动提交（Commit）代码。

## 三、 核心技能功能详解

下表涵盖了 Matt Pocock 技能库中最重要的几项功能：

|                    |      |                                                         |
| ------------------ | ---- | ------------------------------------------------------- |
| 技能名称               | 类型   | 核心作用与新手建议                                               |
| `/ask-matt`        | 用户调用 | **新手必用。** 充当路由，询问它“我现在该用哪个技能”，它会根据现状给出建议。               |
| `/grill-with-docs` | 用户调用 | 建立“统一语言”（Ubiquitous Language）。确保 AI 命名变量、文件时使用项目中定义的术语。 |
| `/wayfinder`       | 用户调用 | 复杂项目导航。当任务“迷雾重重”时，它会创建带依赖关系的子任务图。                       |
| `/research`        | 模型调用 | 后台运行。针对高可信度来源进行调研，并生成带引用的 Markdown 报告。                  |
| `/diagnosing-bugs` | 模型调用 | 规范化 Debug。遵循“复现 -> 最小化 -> 假设 -> 验证 -> 修复 -> 回归测试”的严谨流程。 |
| `/handoff`         | 用户调用 | 会话压缩。当上下文窗口快满时，生成简明文档，以便开启新会话继续工作。                      |

## 四、 特殊技能：`/teach` (学习空间)

这是一个独立于工程流的生产力技能，旨在将 AI 变成私教。

- **作用：** 将当前目录转变为一个“教学工作区”。
- **核心机制：**
    1. **确定使命 (**`**MISSION.md**`**)：** 明确学习目标（例如：掌握 TypeScript Generics）。
    2. **获取资源 (**`**RESOURCES.md**`**)：** 从高可信度来源抓取知识，不依赖模型自身的参数化记忆。
    3. **生成课程 (**`**./lessons/*.html**`**)：** 基于**近侧发展区间 (ZPD)** 理论，生成难度适中的交互式 HTML 课程，包含测验和练习。
    4. **保存记录：** 记录已掌握的知识点，以便下次会话衔接。

## 五、 工程思维要点

1. **统一语言 (Ubiquitous Language)：** 通过 `CONTEXT.md` 消除沟通中的行话障碍。例如，将“课程中某个部分的单元被文件化”简化为“物化级联 (Materialization Cascade)”。这种简洁性可以显著节省 Token 并减少 AI 幻觉。
2. **有状态 vs 无状态：**
    - **无状态技能**（如 `/grill-me`）仅在当前对话有效。
    - **有状态技能**（如 `/grill-with-docs`, `/teach`）会将信息持久化到本地文件，方便长期跨会话协作。
3. **避免“氛围编程”：** 不要直接下令“写个搜索栏”。应通过 `/grill` 确定逻辑，通过 `/prototype` 确认交互，最后通过 `/implement` 与 `/tdd` 确保代码稳健。

_注：本教程基于 Matt Pocock Skills v1.1 版本编写。如需获取最新技能，请运行_ `_npx skills update_`_。_
